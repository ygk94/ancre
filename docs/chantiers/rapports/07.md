## 7. Décisions et raisons

| Décision | Raison |
|---|---|
| `app/` à la racine | le brief le nomme ainsi ; `demo/` appartient au 06 |
| 8004scan par instantané daté, pas par le navigateur | pas d'`Access-Control-Allow-Origin`, requête préliminaire en 400 (MESURÉ 06/10) ; pas de proxy |
| Acte 1 recalculé par un script qui importe le solveur | chaque chiffre de la colonne contrat est reproductible par la commande affichée ; `solver/` n'est pas modifié |
| Verdict de l'acte 1 = `ppr.is_trusted`, θ = 2 % | même règle que le solveur ; θ = celui engagé par l'ensemble du 06 ; « applied off-chain » écrit à l'écran |
| Un seul réducteur pur pour le live et le rejeu | la démo survit à une panne réseau sans code de secours spécifique |
| Live = sondage de `latest.json` (250 ms) | fichier réécrit atomiquement, réducteur idempotent sur `seq`, < 1 bloc |
| Relecture du contrat en live seulement | en rejeu, un fork vivant peut contenir un autre run aux mêmes blocs (fausse alarme) |
| Règle de finalité qui se ferme en cas de doute | jamais de verdict spéculatif : sans flux de blocs, l'écran dit « awaiting finality » |
| `newHeads` seulement sur un fork, et seulement si `monadNewHeads` est inconnu | sur Monad, une tête sans état de commit désactiverait la règle |
| Rythme « presenter » par défaut en rejeu | anvil mine instantanément ; au rythme enregistré, la ferme passe en une seconde |
| Thème sombre, une seule couleur d'accent (contrat), explorer en neutre | skill dataviz : statuts réservés avec icône et mot ; lisible en 1080p |
