## 2. Verdict P2 : **OUI**

Un handler HyperIndex lit le **calldata complet** de la transaction (`fields: { transaction: ["input"] }`). MESURÉ le 28/09 sur de vraies transactions, sans aucune transaction émise :
- `giveFeedback` direct (0xea0b → #4, slash, bloc 54 268 040) : décodé par viem **dans le handler**, 9/9 champs identiques à l'event, via RPC **et** via HyperSync ;
- appel relayé (execution.market, EIP-7702, bloc 108 483 651) : le calldata présent est celui du relais, donc indécodable → audit `UNDECODABLE` ;
- **99 588 octets** (lot Arbitrum sur Ethereum, bloc 19 000 684) reçus intacts via HyperSync (keccak identique au RPC public).

**Conséquence pour 02** : pas besoin d'émettre les `rows` dans un event. **Exigence** : `submitCertificate` appelé **directement** depuis un EOA (pas de multicall, Safe ou relayer). Au-delà de 100 Ko : NON VÉRIFIÉ, faute de transaction réelle plus grosse (le mécanisme ne dépend pas de la taille).

## 4. Décisions techniques et raisons

| Décision | Raison |
|---|---|
| **Envio HyperIndex + HyperSync** (pas de RPC maison) | Bounty D38 ; HyperSync lit tout l'historique de Monad en ~17 s (MESURÉ) ; reorgs gérées |
| **3e chaîne = Optimism** (réversible, 🧑) | 5 arêtes sur 10 émises par des agents (Arbitrum : 0 sur 22) ; 2 944 events contre 5 395 |
| Mode par chaîne (`disable_default_cross_chain`), **aucune entité `@crossChain`** | Un `agentId` n'est unique que sur sa chaîne ; une reorg ne recule que sa chaîne (DOC v3.10). La vue inter-chaînes se fait à la requête (`ChainStats` des 3 chaînes en une requête) |
| Identité **reconstruite depuis les events**, jamais par `eth_call` historique | Monad ne sert que ~40 k blocs d'état (DOC) ; vérifié exact par `check --full` |
| **L'émetteur (D20, D44) n'est pas figé dans l'indexeur** : `RefEdge` est indexé par adresse de client | D44 et l'encodage des alias bougent encore ; ainsi, pas de réindexation. Le consommateur résout l'émetteur depuis `Agent` + `WalletAgents` |
| **Une seule décision d'arête** (`edges.ts`) pour `RefEdge` et l'audit | La règle testée en parité avec le solveur est celle qu'applique l'audit |
| **Audit en parts normalisées** `w / B` avec la ligne vraie du registre | D32 porte sur C = w/B⁺ ; comparer des poids bruts laissait passer la dilution (AM-5.11) |
| `TripleLatest` suivi pour **tous** les tags | Un ensemble engage son propre filtre (D12) ; l'audit doit pouvoir le rejouer |
| Contrôles de cohérence dans un **script externe**, pas de block handler | Le décompte des block handlers dans le quota Cloud n'est pas documenté ; Monad produit ~286 k blocs/jour |
| Pas d'Effect API pour l'instant | Aucun appel réseau n'est nécessaire dans les handlers ; les lectures à la tête sont dans `check.ts` (Multicall3) |
| Copie de `schema_reference.json` dans l'indexeur, **test d'identité** avec `solver/` | Le Cloud interdit les imports hors du dossier ; le test empêche la divergence |
