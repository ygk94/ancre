## 2026-09-28 ~22:30 — E1a : porte P2 (calldata dans un handler) — ✅ VERDICT : OUI

**Verdict P2 : un handler HyperIndex lit le calldata complet de la transaction** via `fields: { transaction: ["input", ...] }` (envio 3.12.1). **Le chantier 02 n'a PAS besoin d'émettre les `rows` dans un event** pour que l'audit fonctionne, à une condition : `submitCertificate` doit être **appelé directement** (`tx.to` = contrat ANCRE). Un appel via un relais, un multicall, un Safe ou un EOA délégué EIP-7702 donne le calldata du relais, qui est indécodable → audit `UNDECODABLE` (HyperSync ne fournit pas de traces pour Monad, DOC).

**Limites du verdict**
- Testé jusqu'à **~100 Ko**. Au-delà (un certificat Registry-verified pourrait peser plusieurs centaines de Ko, ESTIMÉ au tour 5), c'est **NON VÉRIFIÉ**. Le mécanisme ne dépend pas de la taille, mais je n'ai trouvé aucune tx de plus de 100 Ko émettant un event pour le prouver. Sur Monad, la taille d'une tx n'est bornée que par la gas limit de 30 M, et le corps HTTP du RPC public par 8 Mo (vault, « Différences EVM » ligne 30, MESURÉ par le pilote, limite protocolaire non trouvée). Plus gros `register()` sur Monad : 11 332 octets.
- Testé avec `createTestIndexer` (même pipeline de fetch que `envio dev/start`), **pas encore sur Envio Cloud** (1er déploiement le 01/10).
