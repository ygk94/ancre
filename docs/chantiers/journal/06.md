## 2026-10-06 — E3 : format du journal d'événements (`demo/EVENTS.md`) — ✅ (format)

**Fait** : `demo/EVENTS.md`, format `ancre-demo-events-v1`, écrit **avant** les scènes, sur demande du pilote : **le 07 le lit directement dans ce worktree**.
- Fichiers : `demo/out/run-<ts>.jsonl` (append-only, pour le live), `run-<ts>.json` (réécrit atomiquement, pour le rejeu), `latest.json` (chemin fixe).
- **Complément du pilote intégré** : chaque événement qui concerne un agent porte un bloc `agent` à deux colonnes, lu au bloc de l'événement : `explorer` (nombre d'avis, révoqués, clients, **moyenne naïve**) et `contract` (`assess` complet : statut, `trusted`, masse `trustLow` contre `theta`, borne `e`, veto, tag déclencheur résolu). L'écran met à jour les deux colonnes sans requête supplémentaire.
- Blocs `payer` (décision, étape verify/settle, `Reason`, `explain`), `certificate` (miroir du journal du certificateur), `latency` (scène 4 : avis → certificat → refus, en blocs et en ms).

**Décisions**
- Grands entiers en chaînes décimales (WAD, USDC, gas) ; compagnons `…Pct` flottants pour l'affichage seulement.
- Moyenne naïve = **notre** définition (moyenne brute de `value/10^decimals`, tous tags, non révoqués, relue on-chain). La formule de 8004scan n'est pas documentée : l'écran doit écrire « naive average », pas « score 8004scan ».
- Les scènes de refus **signent quand même** (contournement de la garde douce) pour que le refus affiché soit celui du contrat (garde dure, D41/D48).
- Latences étiquetées `fork` / `frozen` / `testnet` : seules celles du testnet se citent comme chiffres Monad (anvil mine instantanément).

**INTERFACE** : aucune demande aux autres chantiers. Toute évolution du format changera la chaîne `format` et sera notée ici.

**Décisions**
1. **θ = 0,02 WAD** (2 %) au lieu de 0,05 : le premier passage à 0,05 refusait les fournisseurs honnêtes (3,46 / 3,95 %, MESURÉ). 2 % laisse une marge ×1,5 sous le pire honnête (3,05 %) et la ferme est à 0.

3. **`demo/` n'importe pas le plugin** (ses `node_modules` et `dist/` ne sont pas dans le dépôt). Les ~40 lignes du blob et des typed data sont portées depuis `plugin/src/lib/payer.ts` et **contrôlées à chaque paiement** contre `paymentDigest` du contrat (dérive = arrêt). Le facilitator émulé reprend `plugin/scripts/local.mjs` (x402-rs : eth_call, estimateGas, envoi avec cette limite).
4. **Certificateur** : le vrai `solver/certifier.py` via `demo/certify.py`. Écarts côté adaptateur seulement : table des nœuds lue par les vues `nodeCount`/`nodeKeyAt` (le RPC testnet limite `eth_getLogs`) ; `--fabricate` ne fait que **simuler** (`eth_estimateGas`), jamais d'envoi ; `--print-set` : **une seule source pour l'ensemble** (le script enregistre exactement le `set_block` du certificateur, et vérifie `computeSetId` = setId Python).
5. **Comptes** : tous dérivés d'une graine (`keccak(graine ‖ label)`). Fork : graine publique (clés de test sans valeur). Testnet : la graine = la clé d'un keystore Foundry chiffré, déchiffré en mémoire (scrypt + aes-128-ctr, MAC vérifié) ; aucun secret dans un fichier, un log ou une ligne de commande.
6. **Opérateur unique** = déployeur + soumetteur attesté (D27) + owner/trésorerie du payeur ; l'opérateur du payeur est une clé distincte (elle ne fait que signer). Ancres = 3 EOA dérivées, jamais wallet d'un agent (**contrôle AM-08.A à chaque `setAgentWallet`**). La ferme a son propre owner ; les wallets de la ferme notent (pas l'owner : garde-fou du registre), sans auto-notation via `agentWallet` (on ne s'appuie pas sur ce trou).
